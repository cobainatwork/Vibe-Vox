# 實測：VoxCPM2 的行內 `(...)` 風格通道能控制什麼

日期：2026-08-05
方法：本機 CPU 容器實跑 `voxcpm 2.0.3`（PyPI 發行版），`openbmb/VoxCPM2` 權重，
`device="cpu"`、`optimize=False`、`normalize` 預設 `False`。共四輪 spike、18 次生成。
聽感判定由使用者執行。

**適用範圍的兩個限制，讀本文前先確認：**

1. **測的是參考實作，不是 production 路徑。** production 走 vLLM-Omni 服務
   `openbmb/VoxCPM2`，那是 `vllm_omni` 自己的實作，不呼叫 `voxcpm` 套件。模型本身的
   取樣特性應共通，端點層行為未驗證。
2. **所有測試的參考音都是合成的**（zero-shot 產物）。真人參考音下的行為未測，見 §5。

---

## 1. 雜訊底線：先有尺才能量

同一個參考音、同一句文字、同一組參數，連續三次生成：

| | 長度 | RMS |
|---|---|---|
| 第 1 次 | 4.16 秒 | 0.02725 |
| 第 2 次 | 3.68 秒 | 0.02070 |
| 第 3 次 | 3.52 秒 | 0.02216 |
| **最大/最小** | **×1.18** | **×1.32** |

**任何小於這兩個比值的差異都不可解讀。** 本文後續所有結論都以此為判準。

先前有兩輪 spike 缺這個基線，導致 `(生氣)` 的音量 ×1.36 一度被當成訊號——它其實貼在
×1.32 的邊緣，單次樣本分不出來。

---

## 2. 定版是功能上的必要條件，不是效能優化

**zero-shot（不給參考音），同一段描述三次：**

| | 長度 |
|---|---|
| 第 1 次 | 4.32 秒 |
| 第 2 次 | 2.56 秒 |
| 第 3 次 | 3.36 秒 |

離散 **69%**，遠超 ×1.18 的雜訊底線。使用者聽感：**三個不同的人。**

**帶參考音（reference clone），同一句三次：** 離散 **18.2%**，貼近雜訊底線。使用者
聽感：**同一個人，速度些微差異。**

故 design 音色若在合成時才從描述重生，同一段對話會逐句換人。ADR-0002 的「建立時
定版」因此是功能上的必要條件——沒有它，多句對話不可用。

---

## 3. 風格通道對「聲學描述」有效

同一參考音、同一句文字，只換前綴：

| 前綴 | 長度 | RMS |
|---|---|---|
| `(angry, shouting, very fast)` | 3.20 秒 | 0.02937 |
| `(gentle, whispering, very slow)` | 4.80 秒 | 0.02142 |
| `(生氣、大聲吼、語速很快)` | 2.72 秒 | 0.03504 |
| `(溫柔、輕聲細語、語速很慢)` | 5.12 秒 | 0.02264 |

| | 音量比（怒/輕） | 長度比（輕/怒） |
|---|---|---|
| 英文前綴 | ×1.37 | ×1.50 |
| **中文前綴** | **×1.55** | **×1.88** |

兩者皆遠超雜訊底線，使用者確認對比明顯。**中文前綴在兩個指標上都強於英文**，且使用者
聽感一致。

**故 Instruction 範例清單（spec User Story 31）應以中文撰寫。**

---

## 4. 風格通道對「情緒標籤」無可測反應

同一參考音、同一句文字，前綴只給情緒詞、**不給任何聲學提示**：

| 前綴 | 長度比 | 音量比 | 超出雜訊？ |
|---|---|---|---|
| `(生氣)` | ×1.05 | ×1.36 | 音量在 ×1.32 邊緣，長度否 |
| `(開心)` | ×1.00 | ×1.17 | 否 |
| `(難過)` | ×1.00 | ×1.01 | 否 |
| `(不耐煩)` | ×1.15 | ×1.17 | 否 |

全部落在雜訊底線內或邊緣。使用者聽感：**五個檔案差別不大。**

**結論：寫 `(不耐煩)` 沒有效果，要寫 `(語速偏快、音量略大、句尾上揚)`。**
Instruction 的範例必須寫聲學實現，不能只寫情緒名稱。

### 量測失敗紀錄

本輪原本加入基頻 F0 作為情感的客觀代理，結果無效：`torchaudio.functional.
detect_pitch_frequency` 在 48 kHz 上以預設參數量到 580 至 725 Hz、標準差 900 Hz，
而人聲基頻約 85 至 255 Hz，標準差不可能大於平均。該欄已丟棄。要用 F0 需先驗證
量測本身在此取樣率下有效。

---

## 5. 未隔離的變項：參考音的表現力

**本文所有結論都建立在合成參考音之上**（`run_1.wav`，zero-shot 產物，4.32 秒，平板）。

情緒在 voice cloning 中通常從參考音繼承表現力。平板的合成參考音可能給不了模型可模仿的
情感範圍，故 §4 的空結果有兩種解釋，本文無法區分：

1. 模型的 `(...)` 通道本身不處理情緒標籤
2. 通道有效，但合成參考音沒有情感範圍可供調度

**唯一的正面證據不是本文測的**：spike #12（情緒 vs 保真）以**真人台灣參考音**在情緒項
PASS。那是 §4 與 #12 之間唯一的重大差異。

**關閉方式**：取一段有表情的真人台灣錄音（5 至 30 秒）當參考音，重跑 §4 的五組，比對
使用者聽感。這需要實際錄音，本機無法產生。

### 對 `type` 欄位的影響

`docs/api/tts.md` 原稱「`type` 對合成行為無影響，兩型能力相同」。本文使該敘述**需要
限縮**：

- **design 音色的參考音必然是合成的**（定版擷取 zero-shot 輸出），故其情感範圍先天
  受 §5 的限制
- **clone 音色的參考音可以是有表情的真人錄音**，情感範圍可能高得多

差異的來源不是型別本身，而是「design 的參考音一定是合成的」這個結構事實。此項在真人
參考音的對照測出來之前，只能標為**可能**，不宜寫成契約。

## 6. 其他實測值

| 項目 | 值 |
|---|---|
| 模型載入（權重已快取，CPU） | 26 至 35 秒 |
| 單次生成（CPU，3 至 5 秒音訊） | 68 至 132 秒 |
| 擴散步數 | 202 |
| 輸出取樣率 | 48 kHz mono |
| 權重下載一次 | 約 5 分 40 秒 |

CPU 數字不可用於 GPU 的容量或延遲規劃，僅記錄以說明 spike 迴圈的可行性。

### 一個 API 版本落差

`VoxCPM._generate` 在 GitHub `main` 有 `seed: Optional[int] = None`，但**發行版
`voxcpm 2.0.3` 沒有該參數**（實跑得到 `TypeError`）。讀原始碼要讀對應版本。

vLLM-Omni 的 `OpenAICreateSpeechRequest` 另有 `seed` 欄位，description 宣稱
「ensures deterministic output」，**是否真的對 VoxCPM2 生效未驗證**——與
`instructions` 欄位同屬「schema 有但可能被靜默忽略」的風險。
